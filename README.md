# Bella's website — Netlify setup

Your original design and links are preserved. The X card replaces “NSFW 18+ MDNI” with the real post count after its first successful fetch. Until the API is working, the original label stays in place. A Netlify scheduled function saves the count in Netlify Blobs every 6 hours; visitors only read that saved value and never trigger paid X requests. Counts older than 48 hours are labeled “last recorded.”

## Deploy to your existing Netlify project

1. Extract this ZIP. Create a GitHub repository (private is fine).
2. Upload the extracted contents, including the `public` and `netlify` folders, `package.json`, `package-lock.json`, and `netlify.toml`, to the repository root. Do not upload the ZIP itself. No credentials belong in GitHub.
3. Open your EXISTING Netlify project. In Project configuration → Build & deploy → Continuous deployment, link the GitHub repository. Keeping the existing project preserves its domain settings.
4. Use `main` as the production branch, leave the base directory and build command empty, and use `public` as the publish directory. The included netlify.toml sets the functions directory automatically. Netlify installs the npm dependencies.
5. In Project configuration → Environment variables, add `X_BEARER_TOKEN` with your bearer token exactly as generated by X. Enable the Functions scope if scope choices appear and set it for Production. Do not URL-decode the token. Save and deploy/redeploy.
6. Ensure your X developer app has API access and sufficient credits. Set an X spending limit appropriate for your budget.
7. After deployment, open Netlify's Functions page, select `refresh-x-count`, and click **Run now**. Check its log for “X post count refreshed successfully.” Automatic refreshes run at 00:00, 06:00, 12:00, and 18:00 UTC every day. The Netlify schedule only runs on published production deploys.
8. Open your website. The X card should show the count. If you previously opened it, allow up to five minutes for the cached response to update or reload after that interval.

## Troubleshooting

- Missing token: ensure the variable is available to Functions and redeploy after adding it.
- X HTTP 401/403: check the token and developer app permissions/access.
- X HTTP 402: check API billing/credits. HTTP 429: wait for the rate limit to reset.
- The original label remains: run the scheduled function manually and inspect its log. A successful deployment alone does not verify your X credentials.
- Do not drag this ZIP onto Netlify Drop. Deploy this project through the linked repository so the functions are built and deployed.

The API makes four scheduled user lookups per day; manual Run now invocations add lookups. Netlify function/storage usage is separate from X billing and subject to your plan. No credentials are included in this project. Live X authentication and Netlify deployment must be verified after setup.
